# 결. V21 — 연속 핀치 지연 제거 및 성능 최적화

## 사용자 문제
- 6개월·1년 뷰에서 너무 많은 개별 구슬이 매 프레임 움직여 버벅거림.
- 손을 놓아도 구슬이 약 0.41초 이상 더 움직인 뒤에야 화면과 제목이 바뀌므로 연속 축소가 답답함.
- 새 제목이 페이드 없이 갑자기 바뀜.

## 구현
1. 1/3/6/12개월 모두 날짜 구슬의 개별 이동(V20) 유지. 무조건 전체 화면을 단순 크로스페이드하지 않음.
2. 제스처 시작 시 다음 뷰는 1회만 사전 구성. 연간 365일 대상에 365개 opacity 속성을 개별 입력하던 과정을 제거하고, 스테이징 CSS 셀렉터로 제어.
3. 전환 중 실시간 이동 계산은 화면 근처의 최대 **76개** 날짜 구슬로 제한하고, 새로 등장하는 날짜는 가까운 **70개**만 표시. 스테이지의 오프스크린 구슬은 확정 시 정상 표시.
4. 손을 놓으면 즉시 `calendarZoom`, 기간, 실제 DOM을 최종 상태로 갱신. 이후 같은 날짜에 대해 찍어둔 화면 좌표를 이용하여 목표 `.mini`에서 짧은 WAAPI 이동(245ms)을 수행함. 이전 410ms 완료 대기 단계 제거.
5. 기존 헤더를 투명하게 지우면서 새 연월 헤더를 바로 표시하는 215ms 페이드/작은 Y 이동. 대기 없이 연도·월 제목이 변경됨.
6. 365개의 개별 click 리스너 대신 달력 컨테이너의 이벤트 위임 1개로 날짜 선택. 미리보기의 버튼은 `inert` 레이어 안에서 비활성화되며, 새 그룹을 달력으로 옮기면 즉시 활성화.
7. 다음 핀치 터치스타트는 정착 애니메이션 중에도 즉시 작동하며, 이전 헤더 잔상을 제거하고 새 방향의 단계를 시작함.
8. 기록 상세는 핀치 도중 숨김, 기존 로컬 데이터 `gyeol-v2`, 감정 혼합 및 기록 저장 유지.
