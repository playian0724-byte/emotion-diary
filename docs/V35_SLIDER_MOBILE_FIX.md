# 결. V35 — 모바일 유통기한 슬라이더 UI 수정

## 문제

V34 실제 모바일 스크린샷에서 네 점, 레일, 라벨용 CSS가 앱 HTML과 일치하지 않아 브라우저 네이티브 파란색 슬라이더가 짧게 보이고 네 시간 라벨이 왼쪽으로 붙었음. 외부 CSS/JS와 HTML의 배포 버전이 일시적으로 엇갈렸을 가능성이 있지만 정확한 원인(네트워크 응답)은 확인되지 않음.

## 해결

- 기존 \`input[type=range]\`는 시각적으로 투명하게 하고, **네 개의 원형 마커**와 2px 녹회색 레일을 별도 그리기로 렌더. 네이티브 range가 드래그·터치 탭·키보드 및 스크린리더 상호작용을 계속 담당.
- 마커는 폭 20px의 같은 크기 슬롯에 놓아 선택점이 커져도 중심 좌표가 움직이지 않음. 레일 좌우 10px과 정확하게 일치.
- 시간 라벨은 각 마커 중심에 맞춰 0%, 33.333%, 66.667%, 100% 위치에 배치.
- 선택된 마커만 초록 원으로 확대, 나머지 마커는 얇은 중립색 아웃라인으로 표시. 선택 구간에만 채도가 낮은 그린 컬러.
- **HTML에 필수 핵심 스타일을 함께 포함**하여 외부 스타일시트의 캐시나 배포가 늦어도 슬라이더 레이아웃과 시각적 입력이 깨지지 않게 함. 최신 전체 CSS는 styles.css에도 동일한 규칙을 반영.
- 설명 간소화. 기존 감정 기록, 보존된 gyeol-v2.settings.editExpiryHours, 유통기한 값과 기록 편집/확대 축소 기능 변경 없음.

## 검증

- 320/375/390/430/520px의 Chromium 모바일 폭 테스트: **각 점과 라벨 중심 오차 최대 0.02px**, 가로 화면 넘침 없음.
- 레일 좌우 끝을 탭하여 1시간 및 7일로 정확히 선택되는 것 확인.
- 24시간 초기 표시, 큰 가독성 있는 기간 제목, 선택된 마커 강조 확인.
- 4단계 1h/24h/72h/168h 로직 유지, 시각 입력·키보드 접근성 구현 유지.
- 실제 아이폰 Safari 배포 환경 화면 검증은 후속 필요.
